# Changelog

Every entry that changes a security property is tagged **[security]**, so an app pinned to an older version can see what a bump fixes. Breaking changes are tagged **[breaking]**, bug fixes **[bug fix]**, and changes to existing default behaviour **[behaviour change]**.

## Unreleased

The first version of the library. Modules are installed with `go get <module-path>@latest`, or used through a `replace` directive.

### Core (`github.com/ubgo/filesystem`, standard library only)

- `Disk` over a six-method `Driver`: keys cleaned and checked for traversal before any driver sees them, content type detected from the bytes, SHA-256 and size computed while streaming, size caps, typed error codes (`CodeOf`, `RetryAfterOf`), batch errors.
- Capabilities declared by each driver and verified by `NewDisk`: copy, move, visibility, prefix and batch deletes, multipart and presigned parts, stored metadata, content type and HTTP headers, conditional writes, presigned PUTs that pin stored headers, and sweeping abandoned uploads.
- Interceptors instead of wrapper drivers, so capabilities are never hidden; `layer` ships `Retry` (honouring `Retry-After`), `Timeout`, `Limit`, `Log`, `Observe` and `Guard`.
- `Manager`, scoped disks and mirrored disks; a DSN `Mux` and `OpenManager` building every disk from the environment.
- Signed URLs on any backend through `signedurl` (key rotation, secrets redacted from every printed form), and public URLs from a configured base.
- `Disk.FS`, a read-only `io/fs.FS` view of any disk; `Disk.TempFile`; `ParseSize` for "10MB" and "1.5GiB".
- Drivers: `local` (sandboxed with `os.Root`, atomic writes, visibility as file modes, multipart) and `memory` (every capability that needs no network).
- Directories: `Disk.MakeDir` and `Disk.DirExists` behind the `Dirs` capability (`DirMaker`), declared by local, memory, sftp, ftp and webdav; on object stores `MakeDir` writes no marker and `DirExists` is true while a key is under the prefix.
- `Disk.FindAbandoned`, the dry run of `SweepAbandoned` (`AbandonedFinder`, the `FindAbandoned` capability, which `NewDisk` refuses without `SweepAbandoned`), on local, memory, s3 (`sweep_uploads=true`), azure, sftp, ftp and webdav, forwarded by `contrib/crypt`; `jobs.SweepAbandoned` gains a dry run listing `jobs.AbandonedItem`s.
- `local.WithDurability`: `DurabilityFull` (default; the changed directories are synced after the rename, so a returned write survives a power cut), `DurabilityFile` or `DurabilityNone`.
- **[bug fix]** **[behaviour change]** `WithURLSigner` now signs every download (`MethodGet`) even on a disk whose driver presigns (S3, GCS, Azure), so a CloudFront or Cloudflare signer in front of a bucket hands out CDN links instead of being silently ignored for raw bucket links; uploads stay with the driver's presigning. `WithURLSigner(s, methods...)` names exactly the methods the signer signs (`MethodGet, MethodPut` routes uploads through it too). A method routed to the signer never falls back to the driver or to an unsigned link; an unknown method is `CodeInvalidArgument`. Mirrored and cached disks declare that their driver presigns downloads only, scoped disks forward the inner driver's answer, and a `Mux` mount reports `Presign`, `PresignHeaders` and `PresignIP` as whichever of driver or signer signs each method can honour.
- `WithContentDetector(sniff.Detector)`: content-type detection for formats the built-in tables do not know (DICOM, STL, camera RAW, Parquet), consulted only when the built-in answer is `application/octet-stream`, so it can never relabel a known type.
- Injectable clocks: `CacheOptions.Now` (copy age against TTL), and `layer.Bandwidth` takes `layer.BandwidthOptions{Now, Sleep}`.
- `WriteOptions.Checksums` asks a write for more digests beside SHA-256 (`Checksum{Name, New, Want}`: MD5 for an existing checksum column, CRC32C to compare with GCS, BLAKE3), computed while the body streams and returned in `Entry.Checksums`; a `Want` that does not match fails the write with `invalid_argument` before the driver commits. The library imports no hash for it; SHA-256 stays the one always computed.
- `local.WithContentType(fn)`: how `Stat` and `List` derive a local file's `Content-Type` from its key; pass `sniff.TypeByExtension` for a table that answers the same on every host instead of the host's `mime.types`. The default is unchanged.
- **[security]** `PresignOptions.Visibility` and `PostPolicy.Visibility`, behind the new `PresignVisibility` capability (attribute; `NewDisk` refuses it without `SetVisibility` and one of `Presign` or `PresignPost`): the driver signs the visibility into the presigned PUT or pins it in the POST form, so the backend stores the upload with it and refuses a request that changes it. A disk that cannot pin an asked visibility returns `unsupported` instead of signing an upload that would silently get another one; a `URLSigner` never pins one. Guard: `TestPresignVisibility`, `TestPresignVisibilityDeclaration` and `TestRoutePresignVisibility` in the core, and `TestPresignVisibility*` in the s3 and gcs adapters.
- `filesystem.ValidateChecksums(list)` checks a `[]Checksum` the way `Disk.Write` does before reading a byte, for layers that compute the same digests themselves; asking a multipart upload for `Checksums` stays `unsupported`, and the error now names the path that can (`upload.Confirm` with `Policy.Checksums`).

### Uploads and serving

- `upload`: `Receive`, the multipart form `Handler` (all or nothing, or `Partial`), direct uploads with `Presign` and `Confirm`/`ConfirmExpected` (declared size and SHA-256), Uppy endpoints, imports with `FromURL` behind an SSRF guard, base64 and data URIs, `Promote` from a cache prefix, and `Sweep` for uploads nobody finished.
- `upload.Policy`: allowed types and extensions decided from the bytes, minimum and maximum size, a total per request, a per-request policy resolver run before any byte is read, stored HTTP headers, key layouts (random, sharded, named with collision handling), `Process` and `Inspect` hooks.
- Upload sessions: `upload.Sessions` issues a token for one key or prefix, valid for a window, with limits no wider than the endpoint's policy; stores keep only the SHA-256 of the secret (`MemorySessions`, or `records/uploadsessions` in the database); `Sessions.Resolver()` narrows `Handler`, `Chunked`, `Uppy`, presigned and tus uploads (`contrib/tus` `Config.Resolve`).
- `fshttp`: signed and public handlers with ranges, ETags and conditional requests, `Cache-Control` by handler, active content always served as an attachment with `nosniff` and a sandboxing CSP, `ServeZip` streaming many objects as one archive, and `ClientMessage` for error text a client may see.
- `sniff` (type detection), `scan` (malware scanning with a clamd client and `Inspect`), `filesystemtest` (a fake disk, the driver conformance suite and upload request and fake image builders).
- `sniff.Detector` and `sniff.DetectWith`, and `upload.Policy.Detector`: a strict allowlist can name formats Go has no signature for instead of allowing octet-stream. An empty or malformed detector answer stays octet-stream (fails closed), and the active-type deny rules still apply to whatever it returns.
- `upload.ChunkedOptions.Now` and `upload.FetchOptions.Now` make chunk takeover, expiry and `Retry-After` dates testable with a fake clock.
- `fshttp.ErrorWriter`, one error envelope for every handler: `fshttp.PublicOptions`, `SignedOptions` and `ZipOptions`, `upload.HandlerOptions` and `UppyOptions`, `recordshttp.Config`, `share.WithErrors` and the `Responder` of `contrib/gin`, `echo`, `fiber` and `chi` take an `Errors` writer that answers every failure in the application's own shape (RFC 9457 problem+json, a `{data, errors}` envelope), with `Retry-After` already set; client text still comes from `fshttp.ClientMessage`. Nil keeps today's output. Success bodies are unchanged.
- `fshttp.RequestVerifier`: a verifier given to `Signed` that also implements `VerifyRequest(r, method)` sees the whole request, so a token in an `Authorization` header, a cookie or the path, or another signing scheme, reaches `Signed`. Signed still fails closed on top: claims without a disk, key or expiry, for another method, or expired are 403.
- `upload.Policy.KeyContext`: a key function that receives the request's context, so a tenant from middleware can go into the key without a per-request policy; `Key` and `KeyContext` together are refused by `Validate`.
- `upload.UppyOptions.OnStored` runs once a completed multipart upload passed `Confirm`, typically to create its row; if it fails, the file is deleted and the complete request fails, so a stored file never lacks its row.
- **[security]** `upload.FetchOptions.Header` (a `User-Agent`, an `Accept`, an internal `Authorization`; Go drops credentials on a redirect to another host) and `FetchOptions.Proxy` (an egress proxy such as Smokescreen, through `CONNECT`). The SSRF guard still decides the destination: the fetch resolves and checks the address itself and asks the proxy to connect to that address, never to the name; the environment's `HTTP_PROXY` is never read. The CONNECT exchange is bounded by the dial timeout, so a proxy that accepts and never answers fails the fetch.
- `fshttp.ZipOptions.CacheControl` replaces the zip's `private, no-store` for a zip that may be cached.
- **[security]** `PublicOptions.InlinePDF` and `SignedOptions.InlinePDF` (off by default) serve a PDF that is not an attachment with `fshttp.InlinePDFCSP` (`default-src 'none'; object-src 'self'`) instead of the sandbox CSP, so a browser's PDF viewer can show it inline. The viewer's script then runs with the file's origin: turn it on only for trusted PDFs or a separate file domain.
- **[security]** `upload.Policy.AllowPublic` and `upload.TicketRequest.Visibility`: a direct-upload ticket may ask for a public object only when the policy allows it; otherwise the request is refused with `permission` before anything is signed, because whoever holds a ticket creates the object. Asking for private, or for nothing, needs no allow. The ticket's PUT then carries the signed ACL header in `Ticket.Headers`, and a form pins an `acl` field. Guard: `TestPresignVisibility` and `TestPresignHandlerVisibility` in `upload` cover the refusal and the pinned header.
- `fshttp.ServeEntry(w, r, disk, entry, ServeOptions{})`: the serve path of `Signed` and `Public`, exported for handlers that do their own access check, with `Range` (206, 416), `If-None-Match` and `If-Modified-Since` (304), ranged backend reads, and the same `nosniff`, sandbox CSP and active-content-as-attachment rules, which nothing in `ServeOptions` can loosen.
- `upload.SuccessWriter` and `Respond` on `upload.HandlerOptions`, `PresignHandlerOptions` (`upload.PresignHandlerWith`), `ChunkedOptions` and `LimitsOptions`: the success bodies (a closed `upload.SuccessBody`) in your API's envelope, as `ErrorWriter` already did for errors. The default bodies are unchanged.
- **[breaking]** `upload.Policy.Checksums` (the same `[]filesystem.Checksum` as `WriteOptions.Checksums`) asks every stored file for more digests beside SHA-256, through `Receive`, the form handler, `FromURL`, `Confirm` and `Chunked`; they are reported in `upload.Result.Checksums` (algorithm name to lowercase hex, omitted from the JSON when nil) and a declared `Want` that does not match is `rejected`. `upload.Result` now holds a map, so it can no longer be compared with `==`.
- `upload.Policy.SignVisibility`: `Presign` signs the policy's `Visibility` into every ticket, so the server, not the client's JSON, decides that an avatar is stored public; `Validate` refuses it without a `Visibility`, and a public one still needs `AllowPublic`. A ticket request asking for another visibility is refused with `permission`. Off by default, so a policy shared with `Receive` changes no existing ticket.
- `upload.Recorded.ContentType`: an idempotent replay answers in the media type the first response used (a `SuccessWriter` in `application/vnd.api+json`, protobuf or HTML), still with 200; an empty one, as in responses recorded before the field existed, replays as `application/json`. A store that persists `Recorded` must keep the new field.
- `fshttp.ServeOptions.Sendfile` and `ServeOptions.InlinePDF`: `ServeEntry` hands the body to a front proxy (`X-Accel-Redirect`, `X-Sendfile`) and serves PDFs inline under `InlinePDFCSP`, as `Public` and `Signed` already could. Both off by default.
- **[bug fix]** `fshttp.ServeEntry` checks the entry's key with `Disk.CleanKey` before it sets any header and answers a refused key (a traversal, a key not from `Stat`) with 400 through the new `ServeOptions.Errors` (nil is `PlainErrors`). It used to send 200 with an empty body, because the body is read only after the status goes out; no bytes were served either way.
- **[bug fix]** `fshttp.Public`, `Signed` and `ServeEntry` open the backend read before the status on a plain GET (no `Range`, no `If-Match`, `If-None-Match`, `If-Modified-Since` or `If-Unmodified-Since`), so a read that fails (the object deleted since `Stat`, a driver failure, a throttled backend) is answered with `StatusOf(err)` and `Retry-After` through the handler's `Errors` writer instead of a 200 with an empty or cut-short body. The opened reader is the one streamed, so a download is still one backend request; ranged, HEAD and conditional requests keep the lazy read, and `Sendfile` opens nothing. A failure after the status (mid-stream) still cannot change it.

### Adapters (each its own module)

- `adapters/s3`: AWS S3 and S3-compatible stores (verified against RustFS and SeaweedFS), per-disk credentials from named environment variables, presigned PUTs and parts, conditional writes behind a flag.
- `adapters/s3`: bring-your-own-bucket through an assumed IAM role (`NewRoleClient`, `RoleOptions`; DSN `role_arn`, `external_id`, `role_session_name`, `role_duration`), renewed automatically and never printing the external ID; a KMS key per tenant on one disk (`Config.SSEKMSKeyFor`) and per write (`RequestOptions.SSEKMSKeyID`).
- `adapters/s3`: `DelegateOptions.Partition` (`PartitionAWS`, `PartitionChina`, `PartitionGovCloud`; derived from the role ARN when empty, a mismatch refused) so `DelegatePrefix` works in GovCloud and China, and `SessionPolicy` returns the session policy it sends.
- `adapters/s3`: `DelegateOptions.KMSKeyARNs` adds one statement allowing the KMS calls a delegated read or write needs on SSE-KMS buckets; entries must be key ARNs in the delegation's partition, without wildcards (alias ARNs refused).
- `adapters/gcs`: Google Cloud Storage, with V4 signing from a key or keyless through IAM on Cloud Run and GKE.
- `adapters/azure`: Azure Blob Storage, with shared-key or user-delegation SAS signing and an abandoned-upload sweep.
- **[behaviour change]** `adapters/azure`: `Config.BlockSize` and `Config.Concurrency` (DSN `block_size`, `concurrency`), bounded by `MinBlockSize` and `MaxBlockSize`. The defaults change from the SDK's 1 MiB and 1 to `DefaultBlockSize` 8 MiB and `DefaultConcurrency` 5, raising the largest single write from about 48.8 GiB to about 390.6 GiB; a body smaller than 8 MiB (before: smaller than 1 MiB) is now sent as one Put Blob instead of staged blocks, and a write holds up to 40 MiB of buffers.
- `adapters/sftp`: SFTP with host-key checking, reconnection bounded by the caller's context, and an abandoned-upload sweep.
- `adapters/ftp`: on a server that refuses to rename over a file (IIS), a replace by `Write` or `Move` no longer deletes the old object first: it is renamed aside into the staging directory and renamed back if the new one cannot be renamed in, so a failed replace keeps the old object. `StrandedError` gains `Previous`, naming the old content when the rename back fails too.
- `adapters/dropbox`: `Copy` and `Move` onto an existing file no longer delete it first, so a failed copy or move leaves the old file in place: the new file is staged under a transient `dropbox.SwapPrefix` name, swapped in, and the swap is rolled back on failure.
- `adapters/gdrive`, `adapters/onedrive`: the documented memory use of a write is corrected to two chunks (the one being sent and the next, read ahead), not one.
- **[bug fix]** **[behaviour change]** `adapters/ftp`: the DSN's FTPS configuration keeps a TLS session cache, so data connections resume the control connection's session as vsftpd's default `require_ssl_reuse` demands (such servers refused every transfer before). New: `ca_file` (a private CA or self-signed server), the `ftps-implicit` scheme (`SchemeImplicit`, port 990 by default), `Config.Dial` and `Config.DialOptions` (a SOCKS proxy, PASV for a NAT that breaks EPSV), `Config.StagingDir`, `Config.IdleCheck`, and `Driver.Do`, which runs a function on a pooled `*ftp.ServerConn` for what the driver does not cover.
- **[bug fix]** `adapters/ftp`: a `Config.TLS` without `ServerName` now verifies the host of `Addr`, as `tls.Dialer` does, on the control connection and on every data connection; before, explicit and implicit FTPS built in code failed every TLS handshake unless `ServerName` was set (the DSN opener always set it).
- `adapters/sftp`: `Config.AllowNonAtomicWrites` accepts a server without `posix-rename@openssh.com` (replacing a key then takes two steps; off by default), `Config.StagingDir`, `Config.FilePublic` and `Config.FilePrivate` (0 skips the chmod); DSN `identity_passphrase_env` for an encrypted key and `agent=true` for the keys of the running ssh-agent.
- `adapters/s3`: `Config.Concurrency`, `Config.ExpectedBucketOwner` and `Config.RequestPayer` (DSN `concurrency`, `expected_bucket_owner`, `request_payer`), the last two signed into presigned URLs too; `Config.PrivateACL` (`CannedBucketOwnerFullControl` for writes into another account's bucket); `RoleOptions.Policy`, `PolicyARNs`, `Tags`, `TransitiveTagKeys` and `SourceIdentity` for the assumed role; `Config.Clock`.
- `adapters/gcs`: `Config.KMSKeyFor` picks the CMEK per object (by tenant prefix) on every write, copy, rewrite, presigned PUT and form; DSN `credentials_file` and `credentials_env`, so two `gs://` disks in one process can act as two service accounts; `Config.Clock`.
- `adapters/azure`: `Config.EncryptionScopeFor` picks the encryption scope per blob; the opener accepts a SAS connection string (with presigning off); `Config.CopyPollInterval` (`DefaultCopyPollInterval`, 50 ms) and `Config.Clock`.
- `adapters/cloudinary`: `Config.ResourceType` (`ResourceRaw` by default, `ResourceImage`, `ResourceVideo`), `TypePrivate`, `Config.Clock`, and a `cloudinary://<api_key>@<cloud_name>?api_secret_env=<VAR>` opener; `adapters/vercelblob`: `Config.CacheMaxAge` (`x-cache-control-max-age`) and a `vercelblob://public` or `vercelblob://private` opener reading the token from `BLOB_READ_WRITE_TOKEN` (or `token_env`).
- `adapters/dropbox`: `Config.RootNamespaceID` and `NamespaceID` (`Dropbox-API-Path-Root`, for team spaces) and `Config.SelectUser` (a team-scoped token acting as a member), and `AuthorizedClient` returns a client that adds the token (`Native` still adds none); `adapters/gdrive`: `Config.Trash` moves removed files to the trash instead of deleting them; `adapters/webdav`: `Config.StagingDir`; `adapters/sqlblob`: `Config.Schema` qualifies the table, and `Config.Clock` stamps rows.
- `adapters/s3`: in `VisibilityACL` mode the disk declares `PresignVisibility` and signs an asked visibility as `x-amz-acl` (a PUT) or an `acl` form field and condition (a POST); not declared with `UnverifiedSignedHeaders`, which would let a client send another ACL.
- `adapters/gcs`: `WithRequestOptions(ctx, disk, key, RequestOptions{KMSKeyName, StorageClass})` sets a KMS key or storage class for one write of one exact key, as the s3 and azure helpers do; in ACL mode with signing, `PresignVisibility` signs `x-goog-acl` into a PUT and pins an `acl` form field.
- `adapters/azure`: `WithRequestOptions(ctx, disk, key, RequestOptions{EncryptionScope, AccessTier, Tags, LegalHold, RetainUntil, RehydrateTier, RehydratePriority})` for one write of one exact key.
- `adapters/azure`: `Config.AccountName` (with `Credential` and `DelegationClientOptions`) signs user-delegation SAS URLs for an endpoint behind a custom domain, Front Door or a private-endpoint name, whose host's first label is not the account; the DSN takes `account` and `endpoint` together for the same (the endpoint must then be https). `Driver.UserDelegationCredential(ctx, until)` returns the disk's own delegation key, bound to that account, for `DelegateOptions.UserDelegation`.
- **[bug fix]** `adapters/sftp`, `adapters/ftp`, `adapters/webdav`: write-only drop folders (a bank or EDI inbox, a partner's upload box) whose server refuses `mkdir` inside `Root` now work. `Config.StagingPath` stages in an absolute directory outside `Root` on the same filesystem (writes stay atomic, no key is reserved); `Config.WriteInPlace` writes each file straight to its key with no staging at all and needs `AllowNonAtomicWrites` (new on ftp and webdav), because a reader can see a file while it arrives and a failed replace leaves the key empty. Under `WriteInPlace` the disk creates nothing at `New`, declares no `SweepAbandoned` or `FindAbandoned`, and sftp declares `ConditionalWrite` through an exclusive create. On webdav, the cleanup of a failed in-place write retries a `423 Locked` answer a bounded number of times, since the server's handler for the aborted PUT can still hold the lock. The three staging fields exclude each other; the default is unchanged.
- `adapters/gcs`: `RequestOptions.RetainUntil` (a retention date set in the same request that creates the object; only lengthens `Config.RetainFor`), `RequestOptions.TemporaryHold` and `RequestOptions.CustomTime`, for one write or copy of one key, so a WORM object is never unprotected between the write and a later `SetHold`. A presigned PUT or form asking for any of them is `unsupported`, since GCS cannot sign them.
- `adapters/gcs`: `Config.PrivateACL` (a `gcs.PredefinedACL`: `ACLPrivate` by default, `ACLProjectPrivate`, `ACLBucketOwnerRead`, `ACLBucketOwnerFullControl`, listed in `PrivateACLValues`) is the ACL private objects get on writes, presigned PUTs, forms and copies, as s3's `PrivateACL` is; it needs `VisibilityACL`, and public ACLs are refused.

### Records (`github.com/ubgo/filesystem/records`, on `ubgo/sqlb`)

- Files as rows attached to the application's models on SQLite, Postgres and MySQL 8: uploads, attachments with roles and order, single-file roles, trash and restore, purge, replace with versions, visibility disks, alt text, caption and title, lookup by SHA-256, events and hooks, a migration ledger.
- Lifecycle: `PurgeOwner`, `PurgeUnattached`, `PurgeScope` to offboard a tenant, `SweepOrphans`, `SweepTrash`, `RenameDisk`.
- **[security]** Quarantine until scanned: `records.Quarantine()` records a file as `StatusQuarantined`; it gets no URL, stream, view, share link or public visibility (`ErrQuarantined`) until `PassScan` releases it (`ReleaseHooks`, then `file.status_changed` and `file.released`); `FailScan` keeps or purges it (`WithScanFailure`), `Scan` runs a `scan.Scanner` and fails closed; `Dedup` never reuses a quarantined object; `recordshttp` `Config.Quarantine` and the processing plugins (variants, dimensions, video, audio, pdf, ocr, vision, videoplatform) wait for the release.
- Plugin `uploadsessions`: upload sessions in the database, shared by every instance.
- Plugins: `audit`, `folders`, `quota` (optionally counting variants and kept versions), `share`, `tags`, `versions`; `recordshttp` exposes the records layer over `net/http`.
- `Store.NewID(prefix)` exposes the Store's ID generator (`WithIDs`); the acl, folders, versions, share, webhooks and quota plugins now use it, so their IDs follow the same scheme as the core tables.
- Plugins follow the Store's clock (`records.WithClock`) by default: acl, folders, versions, locks, share (and its handler) and quota; `quota.WithClock` and `share.NewAttemptLimiterClock` set one explicitly, and `recordshttp` uses the Store's clock.
- `recordshttp`: `Config.Disk` may be empty to route each upload by its policy's visibility through `WithVisibilityDisks` (`Store.RoutesVisibility` reports it), or `Config.DiskFor` chooses the disk per request (a tenant's own bucket) before any byte is read; `Disk` and `DiskFor` together are refused.
- `records.WithActorFunc` and `Store.Actor(ctx)`: an application with its own session type names who a request acts for once, and the Store (`File.UploadedBy`) and every plugin read it; when the function returns `""` the actor set with `WithActor` is used, so the share plugin's depositors are still recorded.
- **[behaviour change]** `records/audit` and `records/locks` now default to `Store.Actor` instead of `records.ActorFrom`, so a Store with `WithActorFunc` records and checks the same actor everywhere; their own `WithActorFunc` and `WithOwnerFunc` still win. Without `WithActorFunc` nothing changes.
- `records.FileQuery.Order` (`OrderNewest` by default, `OrderOldest`, `OrderName`, `OrderNameDesc`, `OrderLargest`, `OrderSmallest`), each a keyset so pagination stays stable; the recordshttp owner list answers one page with `?limit=` or `?cursor=` (`next_cursor` in the response) and the whole list without either, as before.
- `Store.SweepRetentionIn(ctx, scope, rules, now, dryRun)` applies retention rules to one scope, for rules that differ by tenant or plan; `records.WithForeignOwnerTypes` registers owner types spelled the way another framework stores them (`Admin::User`, `App\Models\Post`); custom serve kinds `access.<name>.<action>` for plugins that report served bytes; `records.Action` moved from recordshttp to records (`recordshttp.Action` is an alias), so acl no longer imports recordshttp.
- `records/acl`: `WithLevels` (your own levels and what each includes), `WithLevelFor` (which level an action needs), `WithContainers` (grants on your own containers, such as projects, honoured for every file they hold) and `Grant.ExpiresAt` (migration `acl/0002_grants_expiry`). Deny grants are not modelled.
- `records/share`: `WithAccessCheck`, `WithDeliver` (your own page instead of the redirect), `WithErrors`, `WithLinkLifetime` and `WithUploadPolicy` (a per-request policy for request links) on the handler; `WithTokenBytes` (32 to 64 bytes: never below 256 bits) and `WithMaxLifetime` (can only lower `MaxLifetime`) on the plugin.
- `records/versions`: `WithKeepFunc` decides each file's history (`KeepPolicy{Count, MaxAge}`, failing closed), `Trim` applies it on demand, and `WithRestoreKey` chooses where restored copies go.
- `records/quota`: `WithDimensions` charges every file to counters of your own beside its scope (an organisation across workspaces, a content class), in the same transaction and failing closed; `RecountDimensions` rebuilds them (migration `quota/0004_dimension_usage`). Trash still counts.
- `records/egress`: `WithBucket` meters reads in your own buckets (hours, or each tenant's day in its time zone) instead of UTC days.
- `records/webhooks`: global endpoints for every scope (`AddGlobalEndpoint`, `Register` with `EndpointSpec{Global: true}`; migration `webhooks/0002_webhooks_global`), `RotateSecret` and `RetireSecrets` (every delivery signed with each active secret), `WithSigner`, `WithPayload` (failing the change rather than sending an unpromised shape), `WithBatch` and `WithConcurrency`.
- `records/locks`: WebDAV-style lock tokens (`TokenHolder`, `WithLockToken`, compared in constant time; migration `locks/0002_lock_tokens`) and `WithHolderFunc` for your own rule of who holds a lock. Shared locks are not modelled.
- `records/audit`: `WithHashChainKeyring` rotates the chain key with key IDs (`StaticKeyring`), and `WithSource` (with `WithSourceIP` for the address) logs where each change came from (migration `audit/0004_audit_keys_source`). `records/folders`: `WithNameKey` refuses sibling names that clash under your key (case or Unicode folding).
- `records.WithTablePrefix(prefix)` and `records.WithTableNames(fn)` (a `records.TableNamer`): the Store and every plugin create and query their tables and indexes under other names, migrations and ledger included; `Store.TableName` maps a name for SQL of your own. `Migrate` refuses a mapping that gives two names one table or a name that is not a valid identifier. The default names are unchanged.
- `records/acl`: `WithDeny()` and `Grant.Effect` (`acl.Deny`): a deny on a file, a folder above it or a container holding it refuses that level and every level including it, whatever allows exist. Without the option `Grant` refuses a deny, but `Can` still honours stored ones, so turning it off never turns a refusal into access. Migration `0003_grants_effect`.
- `records/recordshttp`: `Config.Respond` (a `recordshttp.SuccessWriter`) writes the success bodies in your envelope; `records/share`: `WithRespond` does the same for a collection's listing and a request link's upload.
- `records/locks`: `WithSharedLocks()`: several holders at once (`LockShared`, `SharedLocksOf`, `UnlockShared`), each with its own token, for co-editing; an exclusive lock and shared ones exclude each other. Migration `0003_shared_locks`.
- `records/folders`: `WithShortcuts()`: a file keeps one home folder and is also shown in others (`AddShortcut`, `RemoveShortcut`, `Linked`, `ShortcutsOf`), with `folders.shortcut_added` and `folders.shortcut_removed` events. Migration `0003_folder_shortcuts`.
- `records/egress`: `WithPerSubject(kinds...)` adds a breakdown per share link (or other subject of a read) beside the per-scope totals, read with `SubjectDays`. Migration `0002_egress_subjects`.
- The four new plugin migrations run on the next `Migrate` whether or not the option is used, so the option can be turned on later without a schema change.
- `records.File.Checksums` stores `upload.Result.Checksums` on the file row (at most `MaxChecksums`, names of 1 to 32 lowercase letters, digits or dashes, hex values of up to `MaxChecksumBytes`); `NewFile.Checksums` and `NewContent.Checksums` take them, and uploads through the Store pass the result's on. Migration `records/0007_files_checksums` adds a nullable column, so older rows read nil. `contrib/ent` (`FileMixin`), `contrib/gorm` (`File.Checksums`, decoded by `Record`) and `contrib/sqlc` (`schema.sql`, and the whole-row queries `GetFile`, `ListFilesBySHA256`, `ListLiveFiles` and `ListLiveFilesAfter`, so the generated row types carry `Checksums`) follow the new column.
- `records.WithFileOrder(name, records.KeysetOrder(expr, dir, parse, format))`: a Store's own keyset order for `Files` (a case-insensitive name with `sqlb.Lower(records.FileFilename)`, a natural sort key, a collation), with cursors that name it; the built-in orders are unchanged. `DDL.DropIndex` drops an index on every engine.
- `records.ActionTarget.Change` (a `records.Change` with `Visibility`, `Text` and `Previous`): `recordshttp` reads the size-capped body of the visibility, text and set-attachment routes before `Authorize`, so a rule can tell publishing from unpublishing. A refused caller still gets 403 before an unreadable body's 400, so the body's shape leaks nothing.
- `records/acl`: `WithLevelForTarget(acl.LevelMapper)` maps an action to a level with the request's context and target (the file and the change asked); `WithPrecedence(acl.Precedence)` replaces the default `DenyOverrides` with `MostSpecific` (NTFS and SharePoint broken inheritance, where a file allow reopens a folder deny) or the application's own rule over every matching grant (`acl.Match`, with its depth); `WithLevelsPerSubject()` and `RevokeLevel` let a subject hold one grant per level on a resource (with the option, `Migrate` adds `acl/0004_grants_level_key`, which widens the unique key to include the level). Defaults are unchanged.
- `records/audit`: `WithHashChainMAC(audit.Signer)` computes the chain's MACs by key ID outside the process (AWS KMS `GenerateMac`, Azure Key Vault, Vault transit), with `KeyringMAC` adapting a `Keyring`; tags must be `MinMACBytes` to `MaxMACBytes`, and a signer error fails the write or the `Verify`. `WithEntryDetail(fn)` adds request or trace IDs, a user agent or an "on behalf of" to each entry's Detail, without overwriting the event's own keys.
- `records/egress`: `WithBucketContext(egress.BucketContextFunc)` names billing buckets with a context and an error (a tenant's time zone read from the database); `WithSubjectFunc(egress.SubjectFunc)` chooses the subject of each read, so plain file links (`ServeLink`) can be broken down per file.
- `records/quota`: `RecountDimensionsFor(ctx, s, quota.RecountFilter{Keys, Scopes})` rebuilds only some dimension rows from only some scopes, the repair after one organisation changes plan, without a full-Store recount.
- `records/recordshttp` and `records/share`: every success body carries the `records.File` behind it (`AttachedFile.File`, `FileResponse.File`, `StatusResponse.File`, `ListedFile.File`, `DepositResponse.File`, never encoded), so a `Respond` can add dimensions, metadata or variant URLs without a lookup per row. `share.WithUploadDisk(fn)` chooses the disk of each request-link upload (a tenant's own bucket) before any byte is read.
- `records/webhooks`: `WithEndpointPayload(webhooks.EndpointPayloadFunc)` builds each endpoint's own `webhooks.Body` (data, `ContentType`, extra headers such as CloudEvents' `ce-*`), stored with the delivery so a retry sends the same bytes (migration `webhooks/0003_webhooks_headers`); signing, `Host` and framing headers are refused. A `Signer` that implements `webhooks.SecretFormat` generates and checks secrets in its own format (a GitHub-style secret), with the `MinSecretBytes` and `MaxSecretTextBytes` floor kept.
- `records/versions`: `TrimScope(ctx, s, scope)` applies the history policy to every file of a scope that has versions, `TrimPageSize` files per page and one transaction per file; `jobs.VersionsTrim(plugin, store, scopes)` (`jobs.NameVersionsTrim`) schedules it.
- `records/locks`: `HolderRequest.Action` (`ActionReplace`, `ActionTrash`, `ActionPurge`) and `HolderRequest.File`, so a `HolderFunc` can let an admin purge a locked file without overwriting it; `WithTokenFunc(locks.TokenFunc)` renders the 128 random bits of each token in a WebDAV `opaquelocktoken:` or `urn:uuid:` shape, refused if it drops a bit or exceeds `MaxTokenBytes`.
- `records/folders`: `WithFolderShortcuts()` shows a folder inside other folders (`AddFolderShortcut`, `RemoveFolderShortcut`, `FolderShortcutsIn`, `FolderShortcutsOf`; events `folders.folder_shortcut_added` and `folders.folder_shortcut_removed`; migration `folders/0004_folder_folder_shortcuts`).

### Contrib

- `contrib/imaging`: decoding, sanitising and transforms, the `variants` plugin (declared sizes, eager or on demand, unique keys per generation) and the `dimensions` plugin with a backfill; `placeholder` for initials and identicon avatars.
- `contrib/imaging/variants`: `WithDensities` renders 2x/3x copies of each variant, `DensitySrcSet` builds the `srcset`, `HandlerOptions.Density` serves one.
- **[bug fix]** `contrib/imaging/dimensions`, `contrib/video`, `contrib/audio`, `contrib/pdf`: a plugin no longer deletes its metadata keys from files of a type it does not handle, so dimensions and video (which share `width` and `height`) and video and audio (`duration_ms`, `audio_codec`) no longer wipe each other's values whatever the install order, and pdf no longer removes an application's own `pages` or `encrypted` keys from other files. On a replacement across types, only the keys of the old type that the new type does not share are dropped. Pinned by a cross-plugin test in `examples/media/video`.
- `WithLocation` in `contrib/imaging/variants`, `contrib/video`, `contrib/pdf` and `contrib/ocr`: derived objects (variants, posters, previews, text) can go to another disk or key prefix, such as a public CDN disk while originals stay private; the random per-generation key part is kept, and the derived object's disk is recorded (`poster_disk`, `preview_disk`, `text_disk`, `ocr_text_disk`) when it is not the file's. `PosterLocation`, `PreviewLocation` and `TextLocation` read it back.
- **[bug fix]** `contrib/video`, `contrib/pdf`, `contrib/ocr`: `Store.SweepOrphans` no longer deletes posters, previews and OCR texts. - **[security]** `contrib/video`, `contrib/pdf`: the metadata keys naming a derived object (`poster_key`, `poster_disk`; `preview_key`, `preview_disk`, `text_key`, `text_disk`) are dropped from a caller's metadata on a new file of any type, as contrib/ocr already did with its own, so an application passing a user's metadata through cannot let it name another object for the purge to delete or the orphan sweep to keep. Keeping other types' keys (the B2 fix above) had briefly let these through on files the plugins do not describe.
- `contrib/video`, `contrib/pdf`, `contrib/ocr`: the plugins implement `records.DiskRenamer`, so `Store.RenameDisk` rewrites the disk recorded for a derived object on the renamed disk (`poster_disk`, `preview_disk`, `text_disk`, `ocr_text_disk`) in the same transaction, and `PosterLocation`, `PreviewLocation`, `TextLocation`, the sweep and the purge find it under the new name.
- `contrib/archive`: a corrupt or truncated stream is `ErrFormat` from every listing and extraction path.
- `contrib/otel`: OpenTelemetry spans and metrics for every operation.
- **[security]** `contrib/otel`: without `WithKeys`, a failed operation's `exception` event no longer carries the error's text, which named the object key (the driver's message or a `*filesystem.Error`); its message is only `filesystem: <op> <disk>: <code>`. `WithKeys` records the full error.
- `contrib/tus`: resumable uploads over the tus protocol, with a sweep of abandoned sessions.
- **[behaviour change]** `contrib/tus`: `Config.Cors` sets the handler's CORS policy; the default, `DefaultCors()`, is tusd's with `Upload-Session` (`HeaderUploadSession`) added to the allowed headers, so cross-origin uploads with upload sessions work.
